# Technology Stack

**Analysis Date:** 2026-02-05

## Languages

**Primary:**
- Rust 1.93.0 (2026-01-19) - Application core, MIDI processing, harmony engine, GUI

**Secondary:**
- HTML - WASM entry point at `index.html`
- JavaScript (generated) - WASM glue code generated by Trunk build tool

## Runtime

**Environment:**
- Native: Rust native binary (for CLI and desktop GUI builds)
- WASM: WebAssembly (wasm32-unknown-unknown target) for browser deployment

**Package Manager:**
- Cargo 1.93.0 (2025-12-15)
- Lockfile: `Cargo.lock` present (version 4 format)

## Frameworks

**Core:**
- eframe 0.33 - GUI framework (egui-based immediate mode GUI)
  - Optional feature `gui` enables GUI builds
  - Supports both native and WASM targets
  - Includes persistence feature for saving app state

**MIDI Processing:**
- wmidi 4.0 - MIDI message parsing and construction
- midir 0.10 - Native MIDI I/O (native builds only, requires ALSA on Linux)
- Web MIDI API - Browser MIDI access (WASM builds via web-sys)

**CLI:**
- clap 4.x - Command-line argument parsing (native builds only)
  - Uses derive macros for argument definition

**Testing:**
- Built-in Rust test framework (cargo test)

**Build/Dev:**
- Trunk 0.21.14 - WASM build tool and development server
  - Config: `Trunk.toml` specifies build target (`index.html`) and output dir (`dist`)
  - Handles WASM compilation, optimization, and asset bundling

## Key Dependencies

**Critical:**
- anyhow 1.0 - Error handling across entire application
- serde 1.0 + serde_json 1.0 - Serialization for presets, protocol messages, and persistence
- rand 0.8 - Random number generation for humanization features

**WASM-specific:**
- wasm-bindgen 0.2 - Rust/JavaScript interop
- wasm-bindgen-futures 0.4 - Async support for WASM
- web-sys 0.3 - Browser API bindings (MIDI, Canvas, DOM)
  - Features: Navigator, Window, Document, HtmlCanvasElement, MidiAccess, MidiInput, MidiOutput, MidiInputMap, MidiOutputMap, MidiPort, MidiMessageEvent, MidiOptions
- js-sys 0.3 - JavaScript standard library bindings
- console_error_panic_hook 0.1 - Better panic messages in browser console
- getrandom 0.2 with "js" feature - Random number generation for WASM

**Infrastructure:**
- None - Application runs locally or as static WASM bundle

## Configuration

**Environment:**
- No environment variables required for core functionality
- `.env` files not used (confirmed absent from repository)
- Application configuration managed through GUI or CLI arguments

**Build:**
- `Cargo.toml` - Rust package manifest and dependency management
- `Trunk.toml` - WASM build configuration
- `index.html` - WASM entry point with canvas element
- Conditional compilation:
  - `#[cfg(target_arch = "wasm32")]` - WASM-specific code
  - `#[cfg(not(target_arch = "wasm32"))]` - Native-specific code
  - `#[cfg(feature = "gui")]` - GUI-enabled builds

**Features:**
- `default` - CLI mode (no GUI)
- `gui` - Enables eframe GUI
- `wasm` - Implies GUI for browser builds

**Release Profile:**
- Optimization level: "s" (optimize for size)
- LTO: false (faster compilation)
- Strip: true (remove debug symbols)
- Panic: "abort" (smaller binary size)

## Platform Requirements

**Development:**
- Rust toolchain 1.93.0 or later
- For native builds on Linux: libasound2-dev (ALSA development files)
- For WASM builds: wasm32-unknown-unknown target (`rustup target add wasm32-unknown-unknown`)
- Trunk CLI for WASM development and building

**Production:**
- Native: Platform-appropriate binary (no runtime dependencies except system MIDI drivers)
- WASM: Static file hosting (served via Nginx on Fly.io)
  - Deployment: Fly.io (app name: "contrapunk", region: ewr)
  - Container: nginx:alpine serving static files from `/usr/share/nginx/html/`
  - Port: 80 (with forced HTTPS)
  - VM: shared-cpu-1x with 256MB memory
  - Auto-scaling: stops when idle, starts on demand, minimum 0 machines
