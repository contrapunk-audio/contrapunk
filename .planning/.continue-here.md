<completed_work>

- **GUI build fix**: `ScaleFamily` wasn't re-exported from `harmony/mod.rs`, breaking WASM/GUI build. Added to `pub use`.
- **Stuck interchange display**: `harmonize_smart()` didn't clear `last_borrowed_from` when note was in-key, so UI kept showing "Borrowed from X" after returning to in-key notes. Fixed by clearing at top of in-key branch in `scale.rs`.
- **Expanded borrowing sources**: `borrowing_sources()` only had Church modes. Added HarmonicMinor and MelodicMinor at ranges 1-2, Phrygian at range 3+, PhrygianDominant at range 4+, LydianDominant at range 5. This enables interchange for notes like C# in C major (found in C Phrygian).
- **GUIRouterState interchange tracking**: Added `borrowed_notes: HashSet<u8>` and `last_borrowed_from: Option<ScaleMode>` to `GUIRouterState`. Router populates on Note-On, cleans up on Note-Off and exit. Native GUI can now display interchange info.
- **Commit**: `129e31b` pushed to origin/main.
</completed_work>

<remaining_work>

- **Stuck MIDI notes on setting change**: When changing key, mode, voice leading style, voice position, etc. mid-play, `active_notes.clear()` in engine setters destroys the Note-Off tracking. Harmony notes from before the change never get Note-Off sent. An initial fix was attempted (drain_active_notes + flush_active_notes in router) but user reported it made things worse — all MIDIs getting stuck. Reverted. Needs a different approach.
- **Borrowing "too strict"**: User feels modal interchange still doesn't trigger enough. May need further investigation — possibly the harmony *produced* by interchange isn't musical enough, or more scale families need to be in borrowing sources.
- **Phase 7 discussion**: User started `/gsd:discuss-phase 7` (Mic Input) but interrupted to fix bugs. Not started.
</remaining_work>

<decisions_made>

- Borrowing sources now include non-Church modes (harmonic/melodic minor) — musically sound since these are common borrowing sources in jazz and classical harmony.
- `last_borrowed_from` is cleared on every in-key note, not just on interchange calls — ensures UI accurately reflects current state.
- The drain+flush approach for stuck notes was rejected by user (caused worse stuck notes). Need a different strategy — possibly MIDI All Notes Off (CC 123) on all ports, or tracking at the router level instead of engine level.
</decisions_made>

<blockers>
- Stuck MIDI notes on setting change: known issue, no working fix yet. The engine's `active_notes.clear()` in every setter is the root cause but can't simply be removed (harmonies would be wrong after settings change). Need to either (a) send proper Note-Offs before clearing, without the side effects seen in the first attempt, or (b) send MIDI CC 123 (All Notes Off) on all ports as a brute-force approach.
</blockers>
