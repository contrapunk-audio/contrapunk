# Phase 6.8 Research: CI Fix

## Problem Analysis

### Root Cause
The deploy workflow (`trunk build --release`) fails on GitHub Actions because uncommitted local changes include:
1. `src/theme/colors.rs` — PICO-8 palette with `PICO_INDIGO` (used in `widgets.rs` and `mod.rs`)
2. `src/tabs/` — 4 files deleted locally but still in git HEAD
3. `src/piano.rs`, `src/server/session.rs`, `index.html` — modified but uncommitted

The WASM build error is specifically: `error[E0425]: cannot find value PICO_INDIGO in this scope` (3 occurrences).

### CI Workflow Analysis
- Only workflow: `.github/workflows/deploy.yml` (Deploy to Fly.io)
- Triggers on: push to main
- Steps: checkout → install Rust + wasm32 target → cache cargo → install trunk → trunk build --release → copy dist → flyctl deploy
- No separate CI workflow for PRs or tests

### Caching Status
Current caching caches `~/.cargo/registry`, `~/.cargo/git`, and `target/` keyed on `Cargo.lock` hash. This is basic — Trunk and the wasm32 target compilation could benefit from better caching:
- Trunk binary is re-installed every run (`cargo install trunk --locked`)
- No Rust toolchain caching
- Cache key doesn't include toolchain version

### Recent Failures
- 5 most recent runs: 2 in_progress (stuck), 3 failures — all failing at "Build WASM" step
- Same `PICO_INDIGO` error since the color palette was refactored

## Solution

1. Commit all uncommitted source changes so CI has the current code
2. Add a proper CI workflow (build + test on PRs)
3. Improve caching: cache Trunk binary, use rust-cache action, separate native and WASM caches
