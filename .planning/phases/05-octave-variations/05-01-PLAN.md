  <action>
Change `apply_octave_mode` for Mirror to perform TRUE note duplication instead of alternating shifts.

**Approach:** Add a `last_port_map: Vec<usize>` field to `HarmonyEngine` that stores the port index for each note in the most recent harmonize call. The router reads this after calling harmonize.

1. In `HarmonyEngine` struct (engine.rs ~line 25), add field:
   ```rust
   last_port_map: Vec<usize>,
   ```
   Initialize to empty vec in constructors.

2. Add public getter:
   ```rust
   pub fn last_port_map(&self) -> &[usize] {
       &self.last_port_map
   }
   ```

3. Rewrite the Mirror branch in `apply_octave_mode` (line ~243):
   - First, build default port map: `self.last_port_map = (0..notes.len()).collect();`
   - For non-Mirror modes, the port map stays as-is (index i -> port i).
   - For Mirror mode:
     a. Collect harmony notes (indices 1..n) with their original indices
     b. For each harmony note, create +12 and -12 copies (clamped to valid MIDI 0-127, skip if out of range via Note::try_from)
     c. Append copies to the notes vec
     d. For each appended copy, push the ORIGINAL harmony note's index to `last_port_map`
   - Do NOT modify the original harmony notes (keep them at their original pitch)

   Example: notes = [C4, E4, G4] (melody, harm1, harm2)
   After Mirror: notes = [C4, E4, G4, E5, E3, G5, G3]
   port_map = [0, 1, 2, 1, 1, 2, 2]

4. Move `self.last_port_map` population to happen for ALL octave modes (not just Mirror). For non-Mirror: `self.last_port_map = (0..notes.len()).collect()` set at start and left as-is. For Mirror: extended after appending duplicates.

5. Update the config.rs doc comment for Mirror (line ~41) to say:
   "Mirror - duplicate each harmony note in +1 and -1 octaves (tripling harmony notes)"

6. Update `set_octave_mode` doc comment (line ~99) to reflect duplication behavior.

7. Update/add tests:
   - Test that Mirror mode with 3 voices (melody + 2 harmony) produces 7 notes total (1 melody + 2 original harmonies + 4 octave copies)
   - Test that the port_map has correct assignments
   - Test that out-of-range copies (e.g., note at MIDI 120 + 12 would exceed 127) are skipped gracefully
   - Test that Note-Off releases all duplicated notes (harmonize_note_off returns all 7 notes)
   - Ensure existing Spread and BassTrebleSplit tests still pass

<task type="auto">
  <name>Task 2: Update router and server to use port-aware mirror routing</name>
  <files>src/router.rs, src/server/session.rs</files>
  <action>
Update all note routing code to use `engine.last_port_map()` instead of index-based `i < num_outputs` routing.

1. In `handle_note_on_gui` (router.rs ~line 188):
   Replace the routing loop:
   ```rust
   // OLD: for (i, &n) in notes.iter().enumerate() { if i < num_outputs { send_to_port(i, ...) } }
   // NEW:
   let port_map = engine.last_port_map();
   for (i, &n) in notes.iter().enumerate() {
       let port = if i < port_map.len() { port_map[i] } else { i };
       if port < num_outputs {
           let msg = MidiMessage::NoteOn(channel, n, velocity);
           let mut buf = vec![0u8; msg.bytes_size()];
           msg.copy_to_slice(&mut buf)?;
           output.send_to_port(port, &buf)?;
       }
   }
   ```
   Also update harmony_notes state to include ALL harmony notes (duplicates too) -- the existing `notes.iter().skip(1)` loop already handles this since duplicates are appended after melody.

2. In `handle_note_off_gui` (router.rs ~line 225):
   Same pattern -- use `engine.last_port_map()` for port routing. Note: `harmonize_note_off` returns stored notes from `active_notes`, which already includes duplicates (since `harmonize_note_on` stores the full post-duplication result). The port map from Note-Off should match Note-On. Add a `last_port_map` call after `harmonize_note_off` to get correct mapping.

   IMPORTANT: `harmonize_note_off` calls `active_notes.remove()` which returns the stored harmonies. But `apply_octave_mode` is NOT called on Note-Off path -- it just returns stored notes. So `last_port_map` won't be populated. Fix: store port_map alongside notes in `active_notes`. Change `active_notes: HashMap<u8, Vec<Note>>` to `active_notes: HashMap<u8, (Vec<Note>, Vec<usize>)>` in engine.rs. Then `harmonize_note_on` stores `(result[1..], port_map[1..])` and `harmonize_note_off` returns both. Add `pub fn harmonize_note_off_with_ports(&mut self, note: Note) -> (Vec<Note>, Vec<usize>)` or update existing method signature.

   Actually simpler: add a second field `active_port_maps: HashMap<u8, Vec<usize>>` to engine. On note_on, store port_map. On note_off, retrieve and expose via last_port_map. This avoids changing the active_notes type.
