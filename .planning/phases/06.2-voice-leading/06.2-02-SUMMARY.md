# Phase 6.2 Plan 02: Engine Integration Summary

**One-liner:** Suspension state machine and VoiceLeadingProcessor wired into harmony engine pipeline between harmony generation and octave mode.

## What Was Done

### Task 1: Suspension State Machine
- Created `suspension.rs` with `SuspensionState` struct implementing preparation -> suspension -> resolution cycle
- One-chord-delay principle: holds a voice from previous chord, resolves stepwise down on next change
- Deterministic voice selection: highest-indexed harmony voice that changed
- Only active for Palestrina style (enabled flag at construction)
- 6 tests covering hold-resolve cycle, non-Palestrina skip, reset, first chord, unchanged voices, melody protection

### Task 2: Engine Integration
- Added `VoiceLeadingProcessor` private struct with enabled, style, style_rules, previous_voicing, registers, suspension_state
- Wired into `harmonize()` method: runs AFTER harmony generation, BEFORE `apply_octave_mode()`
- Added getter/setter methods: `voice_leading_enabled()`, `voice_leading_style()`, `set_voice_leading_enabled()`, `set_voice_leading_style()`
- VL state resets on key, mode, style, or voice_count change
- Register assignment: 1 voice=Soprano, 2=S+A, 3=S+A+T, 4+=S+A+T+B
- Re-exported `VoiceLeadingStyle` from `harmony::mod.rs`
- 10 new engine tests covering disabled/enabled behavior, resets, melody protection, all modes

## Decisions Made

1. **VoiceLeadingProcessor as private struct** — kept inside engine.rs since it's tightly coupled to engine internals
2. **Previous voicing stored as Vec\<Note\>** — avoids repeated u8-to-Note conversions for suspension processing
