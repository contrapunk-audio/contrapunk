**rules.rs**: Implement rule-checking functions that operate on `&[Note]` (previous voicing) and `&[Note]` (candidate voicing). All functions skip index 0 (melody). Functions:

1. `check_parallel_fifths(prev: &[Note], curr: &[Note]) -> Vec<(usize, usize)>` — returns voice index pairs that move in parallel fifths (both intervals are 7 semitones mod 12, and both voices moved). Check ALL n*(n-1)/2 pairs, not just adjacent.

2. `check_parallel_octaves(prev: &[Note], curr: &[Note]) -> Vec<(usize, usize)>` — same but for parallel octaves/unisons (interval 0 mod 12, both voices moved).

3. `check_voice_crossing(voicing: &[Note], registers: &[VoiceRegister]) -> Vec<(usize, usize)>` — returns pairs where a higher-register voice has a lower MIDI note than a lower-register voice. E.g., if soprano (index 1) has MIDI 60 and alto (index 2) has MIDI 65, that is a crossing.

4. `check_spacing(voicing: &[Note]) -> Vec<(usize, usize)>` — returns adjacent voice pairs (i, i+1) where the interval exceeds 12 semitones, EXCEPT for bass-tenor (the last two voices), which may exceed an octave.

5. `check_motion_independence(prev: &[Note], curr: &[Note]) -> bool` — returns true if all harmony voices (indices 1+) move in the same direction (all up or all down). This indicates poor independence — prefer oblique/contrary motion.

6. Helper: `interval_class(a: Note, b: Note) -> u8` — returns `(a_midi.abs_diff(b_midi)) % 12`.

Implement the chord-level voicing algorithm. This is the core algorithm and MUST be deterministic.

**VoiceRegister enum**:
```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum VoiceRegister {
    Soprano, // MIDI 60-81
    Alto,    // MIDI 55-76
    Tenor,   // MIDI 48-69
    Bass,    // MIDI 40-64
}
```
With `range(&self) -> (u8, u8)` and `valid_placements(&self, pitch_class: u8) -> Vec<u8>` that returns all MIDI notes of that pitch class within the register range (at most 2-3 values).

**`revoice_chord` function** — the main algorithm:

```rust
pub fn revoice_chord(
    harmony_pitch_classes: &[u8],   // pitch classes of harmony notes (indices 1+)
    prev_voicing: Option<&[Note]>,  // previous voicing (None = first chord)
    registers: &[VoiceRegister],    // register per harmony voice
    style_rules: &StyleRules,
) -> Vec<Note>
```

Algorithm (chord-level, NOT greedy per-voice):

1. **Generate candidate complete voicings.** For each harmony voice i, compute `registers[i].valid_placements(harmony_pitch_classes[i])`. Take the cartesian product of all voices' placements. This gives all possible complete voicings. With 3 harmony voices and ~2-3 placements each, that is at most ~27 candidates. Bounded and fast.

2. **Apply hard constraints.** For each candidate voicing, if prev_voicing exists:
   - If `style_rules.hard_reject_parallel_fifths` and `check_parallel_fifths` finds any, REJECT.
   - If `style_rules.hard_reject_parallel_octaves` and `check_parallel_octaves` finds any, REJECT.
   - If any voice leaps more than `style_rules.max_leap_semitones`, REJECT.
   Also check spacing constraints regardless of prev: if `check_spacing` finds violations and style is strict, REJECT (use spacing_violation_penalty magnitude > 50 as threshold for hard reject).

3. **Score remaining candidates.** For each surviving candidate, compute a total score:
   - For each harmony voice: +common_tone_bonus if movement==0, +stepwise_bonus if movement<=2, else leap_penalty * (movement - 2).
   - For each voice pair: parallel_fifths_penalty if parallel 5ths detected, parallel_octaves_penalty if parallel 8ves.
   - voice_crossing_penalty for each crossing detected.
   - all_parallel_motion_penalty if all voices move same direction.
   - spacing_violation_penalty for each spacing violation.

4. **Deterministic tiebreaking.** Sort candidates by (score DESC, then tiebreak). The tiebreak MUST be deterministic and musically meaningful. Use this strict ordering for equal scores:
   a. Prefer voicing with MORE common tones held (count of voices with movement == 0, DESC).
   b. Prefer voicing with MORE stepwise-down motion (count of voices moving -1 or -2 semitones, DESC).
   c. Prefer voicing with MORE stepwise-up motion (count of voices moving +1 or +2 semitones, DESC).
   d. Prefer voicing with SMALLER total absolute movement (sum of |movement| across all voices, ASC).
   e. Prefer voicing with LOWER voice index priority (compare lexicographically by MIDI values, ASC — lower pitch for lower-indexed voices first).

   Implement this as a comparison function on `(i32, usize, usize, usize, i32, Vec<u8>)` tuple where all components are derived from the candidate. This guarantees a total order — NO ties possible.

5. **First chord (no prev_voicing).** When prev_voicing is None, skip movement-based scoring. Instead, prefer voicings where voices are well-spaced (maximize minimum interval between adjacent voices) and within their register centers. Use the same deterministic tiebreak on spacing score.

6. **Fallback.** If all candidates are rejected by hard constraints, relax to soft-penalty-only mode (downgrade hard rejects to large penalties) and re-score. This ensures the algorithm ALWAYS produces output.

**CRITICAL: No randomness anywhere. No `rand` usage. No arbitrary choices. Every branch must resolve deterministically.**
