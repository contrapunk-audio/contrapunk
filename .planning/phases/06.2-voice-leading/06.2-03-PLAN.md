Add voice leading controls to the GUI. Follow the existing pattern used for Octave Mode and Humanization controls.

1. **Add state fields to ContrapunkApp** (or AppState, whichever holds config):
   - `voice_leading_enabled: bool` (default false)
   - `voice_leading_style: VoiceLeadingStyle` (default Free)

2. **Add UI controls** in the settings section, after the existing Octave Mode selector and before Humanization controls. Use a collapsing header or section:

```rust
ui.separator();
ui.heading("Voice Leading");
// Enable/disable toggle
let mut vl_enabled = self.voice_leading_enabled;
if ui.checkbox(&mut vl_enabled, "Enable Voice Leading").changed() {
    self.voice_leading_enabled = vl_enabled;
    // Sync to engine (however engine is accessed — via Arc<Mutex<>> or direct)
    engine.set_voice_leading_enabled(vl_enabled);
}
// Style selector
if vl_enabled {
    ui.label("Style:");
    for style in VoiceLeadingStyle::all() {
        let selected = self.voice_leading_style == *style;
        if ui.selectable_label(selected, style.description()).clicked() {
            self.voice_leading_style = *style;
            engine.set_voice_leading_style(*style);
        }
    }
}
```

3. **Import VoiceLeadingStyle** at the top of app.rs. Follow existing import patterns (likely from `crate::harmony::VoiceLeadingStyle`).

4. **Sync on startup:** Initialize engine voice leading state from app state in the initialization/setup code.

5. **WASM compatibility:** The UI uses egui which works on both native and WASM. No platform-specific code needed. Just ensure the imports compile on both targets.

6. **Handle the shared state pattern:** Check how the existing code syncs GUI state to the engine. If it uses `Arc<Mutex<HarmonyEngine>>`, use the same pattern. If it sends messages to a router thread, follow that pattern. Do NOT introduce a new synchronization mechanism.

Include the VoiceLeadingStyle in the display of current configuration if there is a status panel showing current settings.
