2. Create src/midi/web.rs (gated with `#[cfg(target_arch = "wasm32")]`):
   - `pub async fn request_midi_access() -> Result<MidiAccess, JsValue>` — calls navigator.requestMIDIAccess()
   - `pub fn list_midi_inputs(access: &MidiAccess) -> Vec<(String, String)>` — returns (id, name) pairs by iterating MidiInputMap
   - `pub fn list_midi_outputs(access: &MidiAccess) -> Vec<(String, String)>` — same for outputs
   - `pub fn connect_input(access: &MidiAccess, id: &str, callback: impl Fn(Vec<u8>) + 'static) -> Result<(), JsValue>` — gets MidiInput by id, sets onmidimessage callback that extracts data bytes and calls the Rust callback
   - `pub fn send_to_output(access: &MidiAccess, id: &str, data: &[u8]) -> Result<(), JsValue>` — gets MidiOutput by id, calls send()
   - Use `Rc<RefCell<Vec<Vec<u8>>>>` as a message queue that the onmidimessage callback pushes to and the app drains each frame
   - Follow patterns from RESEARCH.md code examples

3. Update src/midi/mod.rs:

   - Keep existing `#[cfg(not(target_arch = "wasm32"))]` gates on native modules

  <name>Task 2: Add frame-based MIDI polling to GUI app for WASM</name>
  <files>src/app.rs, src/router.rs</files>

1. In app.rs, add WASM-specific fields to AppState (behind `#[cfg(target_arch = "wasm32")]`):
   - `midi_access: Option<MidiAccess>` — stored after async init
   - `midi_queue: Rc<RefCell<Vec<Vec<u8>>>>` — shared with input callback
   - `connected_output_ids: Vec<String>` — selected output device IDs
   - `midi_initialized: bool` — tracks if requestMIDIAccess has been called

2. In ContrapunkApp::new() for WASM:
   - Use `wasm_bindgen_futures::spawn_local` to call `request_midi_access()` asynchronously
   - Store result in AppState via a shared reference (Rc<RefCell<Option<MidiAccess>>>)
   - Populate available_inputs and available_outputs from MidiAccess once available

3. In the update() method for WASM builds:
   - Each frame: drain midi_queue, for each message:
     - Parse MIDI bytes (Note On/Off status bytes)
     - Process through HarmonyEngine (same logic as router.rs native code)

     - Update shared GUI state (input_notes, harmony_notes) for display
   - Call `ctx.request_repaint()` when running (ensures continuous polling)
   - Show "Web MIDI not available" message if browser doesn't support it
   - Show "Requesting MIDI access..." while waiting for permission

4. For the "Start"/"Stop" button in WASM:
   - Start: connect input device callback that pushes to midi_queue
   - Stop: disconnect (or just stop processing)
