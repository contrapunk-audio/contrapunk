# Phase 06.6 Plan 01: Default MIDI Selection Summary

MIDI device selections now persist across app restarts using eframe::Storage with name-based matching and virtual input string constants.

## What Was Built

1. **MidiDefaults struct** - Serializable struct storing input name and output names per slot
2. **Virtual input constants** - `__virtual:note_generator` and `__virtual:computer_keyboard` for round-tripping virtual inputs
3. **build_midi_defaults()** - Snapshots current state to MidiDefaults (resolves indices to names)
4. **apply_midi_defaults()** - Resolves saved names back to port indices (falls back to None if unavailable)
5. **save/load functions** - JSON serialization via eframe::Storage (mirrors preset storage pattern)
6. **App integration** - save() captures on shutdown, new() loads on startup, WASM defers until device enumeration

## Decisions Made

| Decision | Rationale |
|----------|-----------|
| Name-based matching (not indices) | Port indices change between sessions; names are stable |
| String constants for virtual inputs | Virtual inputs have no port name; need stable identifiers |
| Deferred WASM application | Web MIDI devices enumerate asynchronously after page load |
