# Phase 6.6: Default MIDI Selection - Research

**Researched:** 2026-02-02
**Domain:** eframe Storage persistence for MIDI device preferences
**Confidence:** HIGH

## Summary

This phase persists user MIDI device selections across restarts using eframe's `Storage` trait, which already abstracts native file storage and WASM localStorage. The project already has a working pattern for this in `src/preset/storage.rs` -- custom presets are saved/loaded via `storage.set_string()`/`storage.get_string()` with serde_json serialization. MIDI device persistence follows the exact same pattern.

The key design decision is storing **port names** (strings) rather than port indices, since MIDI port indices change between sessions as devices are connected/disconnected. On restore, the app matches saved names against the current device list and falls back to `None` if a device is unavailable.

**Primary recommendation:** Use the existing `eframe::Storage` + `serde_json` pattern from preset storage. Store a simple struct with `input_name: Option<String>` and `output_names: Vec<Option<String>>` (one per slot). Match by name on load.

## Architecture Patterns

### Recommended Approach: Extend Existing Storage Module

```
src/preset/storage.rs  (or new src/midi_prefs.rs)
  - save_midi_defaults(storage, &MidiDefaults)
  - load_midi_defaults(storage) -> MidiDefaults
```

### Pattern 1: MidiDefaults Struct
**What:** A small serializable struct holding device name preferences
**When to use:** Always -- this is the core data model

```rust
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize, Default, Clone)]
pub struct MidiDefaults {
    /// Saved input device name (None = no default)
    pub input_name: Option<String>,
    /// Saved output device names per slot (None = slot unassigned)
    pub output_names: Vec<Option<String>>,
}
```

### Pattern 2: Name-Based Matching on Load
**What:** Resolve saved names to current port indices
**When to use:** In `ContrapunkApp::new()` after `refresh_devices()`

```rust
fn apply_midi_defaults(state: &mut AppState, defaults: &MidiDefaults) {
    // Match input by name
    if let Some(ref saved_name) = defaults.input_name {
        state.input_port = state.available_inputs.iter()
            .find(|(_, name)| name == saved_name)
            .map(|(idx, _)| *idx);
        // Falls back to None if device not found -- no silent failure
    }

    // Match outputs by name per slot
    for (slot_idx, saved) in defaults.output_names.iter().enumerate() {
        if slot_idx >= state.output_slots.len() { break; }
        state.output_slots[slot_idx] = saved.as_ref().and_then(|saved_name| {
            state.available_outputs.iter()
                .find(|(_, name)| name == saved_name)
                .map(|(idx, _)| *idx)
        });
    }
}
```

### Pattern 3: Auto-Save on Selection Change
**What:** Persist defaults whenever user changes device selection (no explicit "Set as Default" button needed)
**When to use:** The `save()` method on `eframe::App` is called automatically by eframe on shutdown. For immediate persistence, also save when selections change.

```rust
// In eframe::App::save():
fn save(&mut self, storage: &mut dyn eframe::Storage) {
    // Existing preset save
    preset_storage::save_custom_presets(storage, self.preset_manager.custom_presets());

    // NEW: save MIDI defaults
    let defaults = MidiDefaults {
        input_name: self.state.input_port.and_then(|idx| {
            self.state.available_inputs.iter()
                .find(|(i, _)| *i == idx)
                .map(|(_, name)| name.clone())
        }),
        output_names: self.state.output_slots.iter().map(|slot| {
            slot.and_then(|idx| {
                self.state.available_outputs.iter()
                    .find(|(i, _)| *i == idx)
                    .map(|(_, name)| name.clone())
            })
        }).collect(),
    };
    save_midi_defaults(storage, &defaults);
}
```

### Pattern 4: WASM Load Timing
**What:** On WASM, devices are enumerated asynchronously after MidiAccess resolves, so defaults must be applied after device list is populated
**When to use:** In the WASM update() block where `midi_initialized` is set to true

```rust
// In update(), WASM block, after populating available_inputs/outputs:
if !self.midi_initialized {
    self.midi_initialized = true;
    // ... populate device lists ...

    // Apply saved defaults now that devices are known
    if let Some(ref defaults) = self.midi_defaults {
        apply_midi_defaults(&mut self.state, defaults);
        self.midi_defaults = None; // consumed
    }
}
```

### Anti-Patterns to Avoid
- **Storing port indices:** Indices change between sessions. Always store names.
- **Storing midir port handles:** Not serializable, session-scoped.
- **Blocking on WASM device enumeration:** Web MIDI is async; load defaults eagerly, apply them lazily when devices appear.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Native/WASM storage abstraction | Custom file + localStorage code | `eframe::Storage` trait | Already abstracts both platforms, already in use |
| Serialization format | Custom string encoding | `serde_json` | Already used for presets, handles Option/Vec natively |
| Persistence timing | Manual save triggers | `eframe::App::save()` callback | Called automatically by eframe on app close |

**Key insight:** This entire feature is a minor extension of the existing preset storage pattern. No new libraries, no new abstractions.

## Common Pitfalls

### Pitfall 1: WASM Async Device Enumeration
**What goes wrong:** Loading defaults in `new()` before devices are enumerated (WASM devices arrive async)
**Why it happens:** On native, `refresh_devices()` is synchronous. On WASM, MidiAccess is async.
**How to avoid:** Store loaded `MidiDefaults` in a field, apply when `midi_initialized` flips to true.
**Warning signs:** Defaults never apply on WASM, always show "Select..."

### Pitfall 2: Virtual Input Sentinels
**What goes wrong:** Saving sentinel values (usize::MAX for Note Generator, usize::MAX-1 for Computer Keyboard) as device names
**Why it happens:** Virtual inputs use sentinel indices that won't match any real port name
**How to avoid:** Store special string constants like `"__virtual:note_generator"` and `"__virtual:computer_keyboard"` for sentinels, or skip persisting virtual inputs entirely (they're not real devices).
**Warning signs:** Saved default is a huge number or garbage name

### Pitfall 3: Stale Defaults After Device Rename
**What goes wrong:** OS or driver updates change a port's name string, breaking the match
**Why it happens:** Port names are not guaranteed stable across OS/driver updates (rare but possible)
**How to avoid:** Accept this as a known limitation; fallback to None is the correct behavior. Do NOT try fuzzy matching.
**Warning signs:** None needed -- fallback is the right behavior

### Pitfall 4: eframe Storage Key Collision
**What goes wrong:** Using a generic key like "settings" that collides with future features
**Why it happens:** eframe storage is a flat key-value store
**How to avoid:** Use a specific key like `"midi_defaults"` (similar to existing `"custom_presets"`)

## Code Examples

### Save/Load Functions (mirror existing preset pattern)
```rust
// Source: project's own src/preset/storage.rs pattern
use serde::{Serialize, Deserialize};

const STORAGE_KEY: &str = "midi_defaults";

#[derive(Serialize, Deserialize, Default, Clone)]
pub struct MidiDefaults {
    pub input_name: Option<String>,
    pub output_names: Vec<Option<String>>,
}

#[cfg(feature = "gui")]
pub fn save_midi_defaults(storage: &mut dyn eframe::Storage, defaults: &MidiDefaults) {
    if let Ok(json) = serde_json::to_string(defaults) {
        storage.set_string(STORAGE_KEY, json);
    }
}

#[cfg(feature = "gui")]
pub fn load_midi_defaults(storage: &dyn eframe::Storage) -> MidiDefaults {
    storage
        .get_string(STORAGE_KEY)
        .and_then(|json| serde_json::from_str(&json).ok())
        .unwrap_or_default()
}
```

### Loading in ContrapunkApp::new()
```rust
// In ContrapunkApp::new():
let midi_defaults = _cc.storage
    .map(|s| load_midi_defaults(s));

// Native: apply immediately after refresh_devices()
#[cfg(not(target_arch = "wasm32"))]
if let Some(ref defaults) = midi_defaults {
    apply_midi_defaults(&mut app.state, defaults);
}

// WASM: store for deferred application
#[cfg(target_arch = "wasm32")]
{ app.midi_defaults = midi_defaults; }
```

## Open Questions

1. **Should virtual inputs (Note Generator, Computer Keyboard) be persisted?**
   - What we know: They use sentinel usize values, not real port names
   - What's unclear: Whether users expect these to be remembered
   - Recommendation: Yes, persist them using special name constants. Users who set Computer Keyboard as default likely want it remembered.
