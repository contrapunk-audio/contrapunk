# Phase 6.10.1: UI Modernization - Context

**Gathered:** 2026-02-25
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the egui-based GUI with a Tauri + Svelte 5 frontend. The Rust core (harmony engine, MIDI handling, humanizer, beat clock) remains as a backend library; the rendering layer moves entirely to web technologies (HTML/CSS/JS via Svelte). Both desktop (Tauri webview) and browser (WASM) deployments use the same Svelte frontend. This phase does NOT add new features — it rebuilds the existing UI in the new stack with a new visual identity.

</domain>

<decisions>
## Implementation Decisions

### Framework Choice
- **Tauri + Svelte 5** (with runes/signals)
- Desktop: Tauri wraps the Svelte app in a native webview
- Browser: Same Svelte app served directly, Rust core compiled to WASM
- Svelte 5 chosen for runes reactivity model and future-forward positioning
- **Drop CLI mode** — desktop app and browser are the only interfaces going forward. Remove `#[cfg(not(feature = "gui"))]` gating

### WASM Compatibility
- **Equal priority** for desktop and browser — both must work fully with the same UI
- Keep **Fly.io** hosting for browser deployment
- **Explore Web MIDI alternatives** — research WebMIDI.js or other wrappers for better browser compatibility during planning
- Rust ↔ Svelte communication abstraction: **Claude's discretion** — determine whether a unified adapter or platform-specific code works better

### Migration Scope
- **Full rewrite** — no hybrid egui+Svelte state. Clean break.
- **Same functionality, new design** — all existing controls (key, mode, voice leading, humanization, scale, octave, presets, etc.) must exist and work, but can be completely redesigned visually and reorganized
- **88-key piano keyboard is sacred** — must be preserved with color-coded keys (input green, harmony orange, generator magenta, interchange amber), always visible
- **Light backend refactor** — adjust Rust API surface to work well with Tauri commands/WASM bindings, but core logic stays intact
- Remove egui/eframe dependency entirely when migration is complete

### Visual Identity
- **Hyper Light Drifter + Ableton Live Session View** — a DAW that feels like exploring a neon-lit dungeon
- **Full HLD aesthetic adoption:**
  - **Color palette** — deep indigo/navy backgrounds with vibrant magenta, teal, pink, cyan accents. Neon-on-dark.
  - **Atmosphere/lighting** — moody glow effects, light bloom, particles, sense of depth and mystery
  - **Literal pixel art** — actual pixel-perfect rendering, blocky fonts, aliased edges, pixel icons
  - **HLD-style UI elements** — minimal HUD design, clean icons, simple shapes, dense but uncluttered
- **DAW layout** inspired by Ableton Live's Session View — grid-based, modular, colorful slots, performance-oriented
- **Animations with performance toggle** — full atmosphere (glow pulsing, particle systems, light bloom) by default, with toggle to disable for lower-powered machines
- **Research-heavy** — the researcher needs to deeply study both Hyper Light Drifter's visual language and Ableton's layout patterns to create a cohesive design system

### Claude's Discretion
- Unified adapter vs platform-specific code for Rust ↔ Svelte communication
- Specific Svelte UI component library (if any) vs custom components
- CSS architecture (Tailwind, CSS modules, plain CSS)
- Tauri version (v1 vs v2) — research best fit
- Build tooling (Vite, SvelteKit, etc.)
- Exact pixel art rendering approach in CSS (scaling, image-rendering, canvas, etc.)

</decisions>

<specifics>
## Specific Ideas

- "It should look damn good" — visual polish is the primary motivation for this phase
- Hyper Light Drifter reference: the game's color palette creates emotional weight through deep indigos with vibrant neon accents. The UI should feel atmospheric, not just functional
- Ableton Session View: grid-based clips, color-coded channels, performance-oriented layout where you can see and interact with everything at once
- The combination should feel like a music tool that lives in a neon-lit world — functional DAW layout with HLD's moody, pixel-art atmosphere
- Keep Press Start 2P pixel font or find one that fits the HLD aesthetic better

</specifics>
