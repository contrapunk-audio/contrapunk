# Phase 6.7: Extended Scale Modes & Barry Harris - Research

**Researched:** 2026-02-02
**Domain:** Music theory scale systems, Rust data modeling
**Confidence:** HIGH

## Summary

This phase extends the existing scale system (currently 9 modes: 7 church + harmonic minor + melodic minor) to include all modes of harmonic minor (7), all modes of melodic minor (7), exotic scales (5), and Barry Harris 6th diminished 8-note scales (2). It also adds a new Barry Harris harmony mode with movement rules.

The critical architectural challenge is that the current `Scale` struct uses a fixed `[u8; 7]` offsets array, which must be generalized to support 8-note Barry Harris scales. The `ScaleMode` enum currently has 9 variants and will grow to ~28. The UI dropdown needs grouping by scale family.

**Primary recommendation:** Use a `Vec<u8>` (or `SmallVec<[u8; 8]>`) for scale offsets instead of `[u8; 7]`, add a `ScaleFamily` enum for UI grouping, and implement Barry Harris movement rules as a new `HarmonyMode` variant.

## Architecture Patterns

### Current Architecture (what exists)

```
config.rs:  ScaleMode enum (9 variants) with intervals() -> [u8; 7]
scale.rs:   Scale struct with offsets: [u8; 7], degree_of(), transpose_diatonic()
engine.rs:  HarmonyEngine with set_scale_mode(), harmonize_single_directed()
modes.rs:   Mode functions: pass_through, diatonic_thirds, etc.
ui.rs:      Flat ScaleMode::all() list in ComboBox
```

### Pattern 1: Variable-Length Scale Offsets
**What:** Replace `offsets: [u8; 7]` with `offsets: Vec<u8>` (or `SmallVec<[u8; 8]>`)
**When to use:** Required for 8-note Barry Harris scales
**Key changes:**
- `ScaleMode::intervals()` returns `Vec<u8>` instead of `[u8; 7]`
- `Scale::degree_of()` iterates over `self.offsets.len()` instead of fixed 7
- `Scale::transpose_diatonic()` uses `self.offsets.len() as i8` instead of hardcoded 7
- All modular arithmetic changes from `% 7` / `/ 7` to `% scale_len` / `/ scale_len`

**Critical locations that assume 7 degrees:**
```rust
// scale.rs line 38: offsets: [u8; 7]
// scale.rs line 107: total_degrees / 7, % 7
// scale.rs line 112: ((total_degrees % 7) + 7) % 7
// scale.rs line 117: octave_shift * 12
// config.rs line 94: intervals() -> [u8; 7]
// scale.rs test line 399: assert count == 7
```

### Pattern 2: Scale Family Grouping for UI
**What:** Add `ScaleFamily` enum and `ScaleMode::family()` method for grouped dropdown
**Example:**
```rust
pub enum ScaleFamily {
    Church,
    HarmonicMinor,
    MelodicMinor,
    Exotic,
    BarryHarris,
}

impl ScaleMode {
    pub fn family(&self) -> ScaleFamily { ... }
    pub fn all_grouped() -> Vec<(ScaleFamily, Vec<ScaleMode>)> { ... }
}
```

### Pattern 3: Barry Harris as HarmonyMode
**What:** Add `BarryHarris` variant to `HarmonyMode` enum with specific movement rules
**Movement rules:** Chord tones move to chord tones, passing/scale tones move to passing/scale tones. In the 8-note scale, notes at even indices (0,2,4,6) are chord tones, odd indices (1,3,5,7) are passing tones.

### Anti-Patterns to Avoid
- **Don't create separate Scale8 struct:** Use one Scale struct with variable-length offsets. Two structs would double all scale-related code.
- **Don't hardcode 7 anywhere:** All degree arithmetic must use `self.offsets.len()`.
- **Don't flatten the scale dropdown:** Use grouped sections (separators or headers) so 28 items are navigable.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Scale interval data | Manual calculation | Lookup tables (hardcoded arrays) | Well-known music theory, no computation needed |
| Mode-of-a-scale derivation | Rotation algorithm | Pre-computed interval arrays per mode | Simpler, no bugs from rotation logic |

**Key insight:** All scale intervals are well-known constants. Pre-compute every mode's intervals as a static array rather than deriving them algorithmically from a parent scale.

## Common Pitfalls

### Pitfall 1: Hardcoded 7-degree Assumptions
**What goes wrong:** Barry Harris 8-note scales break transpose_diatonic, degree_of, snap_to_scale
**Why it happens:** Current code has `% 7` and `/ 7` hardcoded in multiple places
**How to avoid:** Search for all occurrences of `7` in scale.rs and replace with `self.offsets.len()`
**Warning signs:** Tests pass for 7-note scales but 8-note scales produce wrong octaves

### Pitfall 2: Serde Backwards Compatibility
**What goes wrong:** Adding new ScaleMode variants breaks deserialization of saved presets
**Why it happens:** Preset JSON files contain `scale_mode` field with old variant names
**How to avoid:** Use `#[serde(alias = "...")]` or default fallback. New variants should serialize cleanly. Test loading old preset JSON with new code.
**Warning signs:** App crashes on startup when loading saved presets

### Pitfall 3: Modal Interchange with Non-Church Modes
**What goes wrong:** `borrowing_sources()` only returns church modes; interchange won't work for harmonic/melodic minor modes
**Why it happens:** Current borrowing sources are hardcoded to church modes only
**How to avoid:** Either expand borrowing sources to include new mode families, or document that interchange only borrows from church modes (which is musically reasonable)
**Warning signs:** Out-of-key notes in harmonic minor modes always fall back to chromatic intervals

### Pitfall 4: Barry Harris Octave Math
**What goes wrong:** 8-note scale wraps at different interval than 12 semitones
**Why it happens:** Barry Harris 6th diminished scales span exactly 12 semitones (one octave) with 8 notes, so octave_shift calculation still uses 12 semitones. BUT `degrees / scale_len` must use 8 not 7.
**How to avoid:** Octave shift = `total_degrees / scale_len`, semitone wrapping stays at 12.

### Variable-Length transpose_diatonic

```rust
pub fn transpose_diatonic(&self, note: Note, degrees: i8) -> Option<Note> {
    let current_degree = self.degree_of(note)? as i8;
    let note_midi = u8::from(note) as i8;
    let scale_len = self.offsets.len() as i8;  // 7 or 8

    let total_degrees = current_degree + degrees;
    let octave_shift = if total_degrees < 0 {
        (total_degrees - (scale_len - 1)) / scale_len
    } else {
        total_degrees / scale_len
    };
    let new_degree = ((total_degrees % scale_len) + scale_len) % scale_len;

    let current_offset = self.offsets[current_degree as usize] as i8;
    let new_offset = self.offsets[new_degree as usize] as i8;
    let semitone_diff = (new_offset - current_offset) + (octave_shift * 12);

    let new_midi = note_midi + semitone_diff;
    if !(0..=127).contains(&new_midi) {
        return None;
    }
    Note::try_from(new_midi as u8).ok()
}
```

### Barry Harris Movement Rules

```rust
/// Barry Harris harmony: chord tones move to chord tones,
/// passing tones move to passing tones.
pub fn barry_harris(note: Note, scale: &mut Scale, above: bool) -> Vec<Note> {
    let degree = match scale.degree_of(note) {
        Some(d) => d,
        None => return vec![note], // out of scale, pass through
    };

    // In BH 8-note scale: even degrees (0,2,4,6) = chord tones,
    // odd degrees (1,3,5,7) = passing tones.
    // Move by 2 scale degrees to stay in same category.
    let interval = if above { 2 } else { -2 };
    match scale.transpose_diatonic(note, interval) {
        Some(harmony) => vec![note, harmony],
        None => vec![note],
    }
}
```

Note: Moving by 2 degrees in an 8-note scale means chord tone -> chord tone and passing tone -> passing tone, because the even/odd parity is preserved. This is the core Barry Harris concept.

## Open Questions

1. **Should modal interchange borrow from harmonic/melodic minor modes?**
   - What we know: Current borrowing_sources only uses church modes
   - What's unclear: Whether borrowing from HM/MM modes is musically useful
   - Recommendation: Keep church-mode-only borrowing initially; expand later if requested

2. **Should melodic minor be ascending-only or both directions?**
   - What we know: Jazz convention uses ascending melodic minor in both directions (= "jazz minor")
   - What's unclear: Whether classical ascending/descending distinction matters here
   - Recommendation: Use jazz convention (ascending = same as descending). The existing MelodicMinor variant already does this.

3. **Preset compatibility with new ScaleMode variants**
   - What we know: Presets serialize ScaleMode via serde
   - What's unclear: How many saved presets exist in the wild
   - Recommendation: New variants deserialize cleanly (they're additive). Old presets won't reference new modes. Test that deserialization of existing preset JSON works.
