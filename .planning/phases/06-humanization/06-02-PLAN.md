- Implement `Ord`/`PartialOrd` for `ScheduledNote` — reverse ordering so smallest `send_at_ms` is popped first (use `Reverse` pattern or invert comparison)
- `DelayQueue` struct wrapping `BinaryHeap<Reverse<ScheduledNote>>` (or custom Ord)
- `DelayQueue::new() -> Self`
- `DelayQueue::push(&mut self, note: HumanizedNote, now_ms: f64)` — computes `send_at_ms = now_ms + note.delay_ms as f64` and pushes
- `DelayQueue::drain_ready(&mut self, now_ms: f64) -> Vec<HumanizedNote>` — pops all notes where `send_at_ms <= now_ms`, returns them in order
- `DelayQueue::is_empty(&self) -> bool`

**src/humanize/metronome.rs:**
- `Metronome` struct with `enabled: bool`
- `Metronome::new() -> Self`
- `Metronome::generate_click(&self, beat_number: u8) -> Vec<u8>` — returns raw MIDI bytes for NoteOn on channel 10 (index 9 in 0-based). Beat 0 (downbeat) uses MIDI note 76 (high woodblock), other beats use 77 (low woodblock). Velocity 100.
- `Metronome::generate_click_off(&self, beat_number: u8) -> Vec<u8>` — NoteOff for the same note on channel 10.
- Use `wmidi::MidiMessage::NoteOn(Channel::Ch10, ...)` to build bytes. Channel 10 in wmidi is `Channel::Ch10`.

**Changes to GUIRouterState:**
- Add `pub humanize_config: HumanizeConfig` field (so GUI can read/write config)

**Changes to `run_gui_router_inner`:**
- After creating `engine`, create `Humanizer::new(HumanizeConfig::default())` and `DelayQueue::new()` and `Metronome::new()`
- Add a helper: `fn now_ms() -> f64` that returns `std::time::Instant` elapsed since a stored epoch as f64 ms. Store `let epoch = std::time::Instant::now();` at router start. `now_ms = epoch.elapsed().as_secs_f64() * 1000.0`.
- In the main loop, BEFORE recv_timeout:
  1. `humanizer.tick(now_ms())` — update beat clock
  2. Sync humanizer config from shared state: `humanizer.update_config(state.lock().unwrap().humanize_config.clone())`
  3. Check metronome: if `humanizer.config().metronome_enabled && humanizer.clock().beat_crossed().is_some()`, generate click, send to first output, schedule click-off after 50ms via delay queue
  4. Drain delay queue: `for note in delay_queue.drain_ready(now_ms()) { send note to output }`
- In the recv_timeout Ok branch, call process_midi_message_gui as before but pass `&mut humanizer` and `&mut delay_queue` and `now_ms`.

**Changes to `handle_note_on_gui`:**
- After `engine.harmonize_note_on(note)`, iterate over harmony notes (skip index 0 = melody).
- For index 0 (melody): send immediately as before (no humanization).
- For indices 1+ (harmony): call `humanizer.humanize_note_on(note, channel, velocity, port)` to get `HumanizedNote`.
  - If `delay_ms == 0`: send immediately.
  - If `delay_ms > 0`: push to `delay_queue.push(humanized, now_ms)`.

**Changes to `handle_note_off_gui`:**
- Same pattern: index 0 sends immediately, indices 1+ go through `humanizer.humanize_note_off(...)`.
- Note-Off delay = jitter + duration_delta. If delay > 0, queue it; else send immediately.
- For queued Note-Off, the `HumanizedNote.is_note_off` flag tells the drain loop to send NoteOff instead of NoteOn.

**Drain loop helper** (new function or inline):
```rust
fn send_humanized_note(note: &HumanizedNote, output: &mut OutputRouter) -> Result<()> {
    let msg = if note.is_note_off {
        MidiMessage::NoteOff(note.channel, note.note, note.velocity)
    } else {
        MidiMessage::NoteOn(note.channel, note.note, note.velocity)
    };
    let mut buf = vec![0u8; msg.bytes_size()];
    msg.copy_to_slice(&mut buf)?;
    output.send_to_port(note.port, &buf)?;
    Ok(())
}
```
