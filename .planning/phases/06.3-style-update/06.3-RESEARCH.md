# Phase 6.3: Style Update - Research

**Researched:** 2026-01-30
**Domain:** egui theming, custom widgets, tabbed layouts, preset systems, persistence
**Confidence:** MEDIUM

## Summary

This phase transforms Contrapunk's GUI from default egui styling into a steampunk/retro-game themed application with tabbed navigation, musical style presets, and custom-painted widgets. The current codebase uses eframe 0.33 with egui, has a left SidePanel + CentralPanel layout, and custom Painter-based rendering (piano keyboard). No serde dependency exists yet.

The core challenge is building heavily custom-themed egui widgets (ornate sliders, gear knobs, rune icons) within egui's immediate mode paradigm. egui supports full custom painting via the Painter API and allocate_painter(), and the codebase already demonstrates this pattern in `piano.rs`. Tabbed navigation is best done with a simple enum-based tab state rather than a heavy docking library, since the tabs are fixed (Play/Craft/Settings). Preset persistence requires adding serde and using eframe's built-in Storage trait, which works on both native (filesystem) and WASM (localStorage).

**Primary recommendation:** Build the theme system as a centralized `ContrapunkTheme` struct applied via `ctx.set_visuals()`, implement all custom widgets using egui's Painter API (not external widget crates), use a simple enum for tab navigation, and add serde for preset serialization with eframe's Storage for persistence.

### Pattern 1: Centralized Theme via Visuals
**What:** Apply a custom dark theme by constructing an `egui::Visuals` struct and calling `ctx.set_visuals()` once at startup.
**When to use:** At app initialization and whenever theme parameters change.
**Example:**
```rust
// Source: https://docs.rs/egui/latest/egui/style/struct.Visuals.html
fn apply_steampunk_theme(ctx: &egui::Context) {
    let mut visuals = egui::Visuals::dark();
    visuals.override_text_color = Some(Color32::from_rgb(255, 215, 140)); // warm gold text
    visuals.widgets.noninteractive.bg_fill = Color32::from_rgb(25, 20, 15); // dark brown bg
    visuals.widgets.inactive.bg_fill = Color32::from_rgb(45, 35, 25);
    visuals.widgets.hovered.bg_fill = Color32::from_rgb(120, 85, 40); // copper hover
    visuals.widgets.active.bg_fill = Color32::from_rgb(180, 120, 50); // amber active
    visuals.selection.bg_fill = Color32::from_rgb(180, 120, 50);
    visuals.extreme_bg_color = Color32::from_rgb(15, 12, 8);
    visuals.panel_fill = Color32::from_rgb(20, 16, 12);
    visuals.window_fill = Color32::from_rgb(25, 20, 15);
    visuals.window_rounding = egui::Rounding::same(8.0);
    ctx.set_visuals(visuals);
}
```

### Pattern 2: Custom Widget via Painter API
**What:** Build ornate sliders, knobs, and decorative elements using egui's Painter drawing primitives.
**When to use:** For all themed interactive controls (sliders, buttons, decorative frames).
**Example:**
```rust
// Source: https://docs.rs/egui/latest/egui/struct.Painter.html
fn ornate_slider(ui: &mut egui::Ui, value: &mut f32, range: std::ops::RangeInclusive<f32>) -> egui::Response {
    let desired_size = egui::vec2(ui.available_width(), 24.0);
    let (rect, response) = ui.allocate_exact_size(desired_size, egui::Sense::click_and_drag());

    if let Some(pos) = response.interact_pointer_pos() {
        let t = ((pos.x - rect.left()) / rect.width()).clamp(0.0, 1.0);
        *value = *range.start() + t * (*range.end() - *range.start());
    }

    if ui.is_rect_visible(rect) {
        let painter = ui.painter();
        // Rail (track)
        let rail_rect = egui::Rect::from_center_size(rect.center(), egui::vec2(rect.width(), 4.0));
        painter.rect_filled(rail_rect, 2.0, Color32::from_rgb(60, 45, 30));
        // Fill
        let t = (*value - *range.start()) / (*range.end() - *range.start());
        let fill_rect = egui::Rect::from_min_max(rail_rect.left_top(), egui::pos2(rail_rect.left() + t * rail_rect.width(), rail_rect.bottom()));
        painter.rect_filled(fill_rect, 2.0, Color32::from_rgb(200, 150, 50));
        // Knob (gear-shaped would need more complex path drawing)
        let knob_x = rect.left() + t * rect.width();
        painter.circle_filled(egui::pos2(knob_x, rect.center().y), 8.0, Color32::from_rgb(220, 170, 60));
        painter.circle_stroke(egui::pos2(knob_x, rect.center().y), 8.0, egui::Stroke::new(2.0, Color32::from_rgb(140, 100, 30)));
    }
    response
}
```

### Pattern 3: Simple Enum Tab Navigation
**What:** Use a Rust enum + `ui.selectable_label()` for tab switching, with the piano/notes panel always visible.
**When to use:** Fixed tab set (Play/Craft/Settings).
**Example:**
```rust
#[derive(Clone, Copy, PartialEq)]
enum Tab { Play, Craft, Settings }

// In update():
egui::TopBottomPanel::top("tab_bar").show(ctx, |ui| {
    ui.horizontal(|ui| {
        ui.selectable_value(&mut self.active_tab, Tab::Play, "Play");
        ui.selectable_value(&mut self.active_tab, Tab::Craft, "Craft");
        ui.selectable_value(&mut self.active_tab, Tab::Settings, "Settings");
    });
});
// Piano always visible in bottom panel
egui::TopBottomPanel::bottom("piano_panel").show(ctx, |ui| {
    self.draw_piano(ui);
});
// Tab content in central panel
egui::CentralPanel::default().show(ctx, |ui| {
    match self.active_tab {
        Tab::Play => self.draw_play_tab(ui),
        Tab::Craft => self.draw_craft_tab(ui),
        Tab::Settings => self.draw_settings_tab(ui),
    }
});
```

### Pattern 4: Preset as Serializable Bundle
**What:** A preset struct containing all musical parameters, with serde Serialize/Deserialize.
**When to use:** Built-in presets defined as constants, custom presets saved/loaded via JSON.
**Example:**
```rust
#[derive(Clone, Debug, Serialize, Deserialize)]
pub struct StylePreset {
    pub name: String,
    pub persona: String,          // e.g., "The Alchemist"
    pub genre: String,            // e.g., "Jazz"
    pub harmony_mode: HarmonyMode,
    pub voice_leading_enabled: bool,
    pub voice_leading_style: VoiceLeadingStyle,
    pub octave_mode: OctaveMode,
    pub humanize_config: HumanizeConfig,
    pub is_builtin: bool,
}
```

### Pattern 5: eframe Storage for Cross-Platform Persistence
**What:** Use eframe's `Storage` trait for saving custom presets. Works on native (filesystem) and WASM (localStorage) identically.
**When to use:** Saving/loading custom presets.
**Example:**
```rust
impl eframe::App for ContrapunkApp {
    fn save(&mut self, storage: &mut dyn eframe::Storage) {
        let json = serde_json::to_string(&self.custom_presets).unwrap_or_default();
        storage.set_string("custom_presets", json);
    }
}

// In ContrapunkApp::new():
if let Some(storage) = cc.storage {
    if let Some(json) = storage.get_string("custom_presets") {
        if let Ok(presets) = serde_json::from_str(&json) {
            app.custom_presets = presets;
        }
    }
}
```

### Anti-Patterns to Avoid
- **Overriding egui Visuals per-widget in update():** Apply theme once at startup or on change, not every frame. Per-frame `set_visuals()` is wasteful.
- **Using egui_dock for fixed tabs:** Adds unnecessary complexity, dependencies, and layout issues for a simple 3-tab interface.
- **Raw web-sys localStorage for WASM persistence:** eframe's Storage trait already abstracts this. Using raw web-sys would break native builds.
- **Storing preset data as separate key-value pairs:** Serialize the whole preset list as a single JSON blob for atomic save/load.
- **Trying to embed OpenGL/WGPU shaders for animations:** Keep animations in egui's Painter API for cross-platform compatibility (native + WASM). PaintCallback with glow/wgpu would work but is fragile across backends.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| JSON serialization | Custom string formatting | serde + serde_json | Edge cases with escaping, nested structures |
| Cross-platform storage | Platform-specific file/localStorage code | eframe::Storage trait | Already abstracts native vs WASM; requires `persistence` feature flag |
| Color palette management | Scattered Color32 literals | Centralized theme struct with named color constants | Consistency, easy to adjust |
| Slider interaction math | Custom pointer tracking | egui's `Response` + `interact_pointer_pos()` | Handles edge cases (drag beyond rect, multi-touch) |

**Key insight:** egui already provides the building blocks (Painter, Visuals, Storage, Response) for everything this phase needs. The work is composition and custom painting, not fighting the framework.

## Common Pitfalls

### Pitfall 1: Animations Draining Battery / CPU
**What goes wrong:** Calling `ctx.request_repaint()` every frame for ambient animations causes 100% CPU usage even when idle.
**Why it happens:** Immediate mode GUI only repaints when requested. Continuous animation means continuous repainting.
**How to avoid:** Use `ctx.request_repaint_after(Duration::from_millis(33))` for 30fps ambient animations instead of `request_repaint()`. When MIDI is actively playing, full-speed repaints are already happening. Only add ambient animation repaints when idle.
**Warning signs:** High CPU usage when no MIDI input, fan spinning up.

### Pitfall 2: Custom Widgets Not Handling All Interaction States
**What goes wrong:** Custom-painted sliders/knobs look wrong when hovered, clicked, or dragged outside bounds.
**Why it happens:** Missing handling of `response.hovered()`, `response.has_focus()`, drag-outside-rect behavior.
**How to avoid:** Always check `response.hovered()` and `response.dragged()` for visual feedback. Use `response.interact_pointer_pos()` (not `response.hover_pos()`) for drag values. Clamp values to range.
**Warning signs:** Slider "sticks" when dragging fast, no visual feedback on hover.

### Pitfall 3: Layout Breakage During SidePanel-to-Tabs Refactor
**What goes wrong:** Moving controls from SidePanel to tab content breaks egui panel ordering rules. egui requires side/top/bottom panels before CentralPanel.
**Why it happens:** egui's layout is order-dependent. Panels must be added in the correct order.
**How to avoid:** Refactor in stages: (1) add tab bar in TopBottomPanel, (2) move piano to BottomPanel, (3) convert SidePanel content into CentralPanel tab content. Test after each step.
**Warning signs:** Panic on "CentralPanel already added", empty areas, overlapping content.

### Pitfall 4: Serde Derive on Enums Without Repr
**What goes wrong:** Adding `Serialize/Deserialize` to existing enums like `HarmonyMode`, `VoiceLeadingStyle`, `OctaveMode`, `Key` may produce unexpected JSON representations.
**Why it happens:** Serde serializes Rust enums as `{"variant": value}` by default, not as simple strings.
**How to avoid:** Add `#[serde(rename_all = "snake_case")]` or implement custom serialize/deserialize. For simple enums, `serde(rename_all)` is sufficient. Test serialization output.
**Warning signs:** Presets produce verbose JSON like `{"mode":{"DiatonicThirds":[]}}` instead of `"diatonic_thirds"`.

### Pitfall 5: eframe persistence Feature Flag Missing
**What goes wrong:** `cc.storage` returns `None`, custom presets never saved.
**Why it happens:** eframe's `persistence` feature must be explicitly enabled.
**How to avoid:** Add `eframe = { version = "0.33", features = ["persistence"] }` in Cargo.toml. The feature enables `ron` and `serde` internally for eframe.
**Warning signs:** `cc.storage` is always `None`, `save()` never called.

### Pitfall 6: Built-in Presets Accidentally Mutated
**What goes wrong:** User modifications to a built-in preset override the original.
**Why it happens:** Storing built-ins and customs in the same Vec, or forgetting the `is_builtin` guard.
**How to avoid:** Separate built-in presets (static/const data) from custom presets (persisted). Built-in list is always freshly constructed from code. "Save" on a built-in always creates a new custom preset.
**Warning signs:** Built-in preset values change between sessions, "Reset" doesn't restore defaults.

### Animated Background (Gear Rotation)
```rust
// In update(), before panels:
let time = ctx.input(|i| i.time); // seconds since start
// ... in a background painter:
let angle = time as f32 * 0.5; // slow rotation
let center = rect.center();
let radius = 30.0;
for i in 0..8 {
    let tooth_angle = angle + (i as f32) * std::f32::consts::TAU / 8.0;
    let outer = egui::pos2(
        center.x + (radius + 5.0) * tooth_angle.cos(),
        center.y + (radius + 5.0) * tooth_angle.sin(),
    );
    let inner = egui::pos2(
        center.x + radius * tooth_angle.cos(),
        center.y + radius * tooth_angle.sin(),
    );
    painter.line_segment([inner, outer], egui::Stroke::new(3.0, Color32::from_rgb(120, 85, 40)));
}
painter.circle_stroke(center, radius, egui::Stroke::new(2.0, Color32::from_rgb(100, 70, 30)));
// Request gentle repaint for animation
ctx.request_repaint_after(std::time::Duration::from_millis(33));
```

### Decorative Frame Around App
```rust
fn draw_ornate_frame(painter: &egui::Painter, rect: egui::Rect) {
    let border_color = Color32::from_rgb(160, 110, 40);
    let corner_color = Color32::from_rgb(200, 150, 60);
    // Outer border
    painter.rect_stroke(rect, 4.0, egui::Stroke::new(3.0, border_color), egui::StrokeKind::Inside);
    // Inner border (double-line effect)
    let inner = rect.shrink(5.0);
    painter.rect_stroke(inner, 3.0, egui::Stroke::new(1.0, border_color), egui::StrokeKind::Inside);
    // Corner accents (circles at corners)
    let r = 6.0;
    for pos in [rect.left_top(), rect.right_top(), rect.left_bottom(), rect.right_bottom()] {
        painter.circle_filled(pos, r, corner_color);
    }
}
```

## Open Questions

1. **Complex gear/cog shape rendering in egui Painter**
   - What we know: Painter supports circles, lines, rects, bezier curves, and arbitrary Mesh/Shape. Gear teeth can be drawn with line segments or bezier paths.
   - What's unclear: Performance of complex gear paths drawn every frame (many vertices). Whether egui's Mesh API is sufficient for smooth gear outlines or if simpler geometric approximations are needed.
   - Recommendation: Start with simple geometric gear shapes (circles + rectangles for teeth). Profile. Only optimize if performance is an issue.

2. **Character avatar images for presets**
   - What we know: egui_extras supports image loading (PNG). Alternatively, avatars can be drawn procedurally using Painter.
   - What's unclear: Whether to use embedded PNG assets (increases binary size) or procedural drawing (more code, smaller binary, fits steampunk aesthetic better).
   - Recommendation: Use procedural Painter-drawn icons/symbols for character avatars. Fits the steampunk aesthetic, avoids asset management, works identically on native and WASM.

3. **Music-reactive animations responding to MIDI input**
   - What we know: The app already tracks `input_notes` and `harmony_notes` in real time. Animation intensity can be driven by note count or velocity.
   - What's unclear: Exact visual effect to use (particle burst, glow pulse, gear speed change).
   - Recommendation: Start with simple glow/color pulse on note events. Add complexity later if desired.
