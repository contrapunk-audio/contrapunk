# Phase 6.1 Plan 01: WASM Humanizer Integration Summary

**One-liner:** Wired Humanizer, DelayQueue, and Metronome into WASM MIDI path so humanization effects work in-browser.

## What Was Done

### Task 1: Add WASM humanizer fields and config sync
Added `wasm_humanizer: Humanizer`, `wasm_delay_queue: DelayQueue`, `wasm_metronome: Metronome`, and `wasm_clock_started: bool` fields to ContrapunkApp (all `#[cfg(target_arch = "wasm32")]`). In the update() frame loop: syncs humanize_config each frame, ticks beat clock with `performance.now()`, drains delay queue sending ready notes to Web MIDI, and checks metronome beat crossings sending channel 10 clicks.

### Task 2: Route WASM harmony notes through humanizer
Modified `handle_wasm_note_on` and `handle_wasm_note_off` to route harmony notes (index 1+) through the Humanizer. Melody (index 0) passes through unchanged. Humanized notes with zero delay send immediately; non-zero delay notes are pushed to the delay queue. Note-Off inherits the matching jitter from the Humanizer's active_humanization HashMap.

## Decisions Made

1. **Melody bypass:** Index 0 (melody) is never humanized -- only harmony voices get jitter/velocity/swing treatment.
2. **Clock lifecycle:** Beat clock starts on first running frame, stops on stop(), resets wasm_clock_started flag.

## Deviations from Plan

None -- plan executed exactly as written.
