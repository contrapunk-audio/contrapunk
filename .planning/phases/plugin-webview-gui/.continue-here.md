<context>
The overall goal is: one Svelte codebase, three targets (Tauri desktop, browser WASM, plugin webview).
The adapter pattern (types.ts → tauri.ts / wasm.ts / plugin.ts) is the key abstraction.
The plugin adapter maps window.plugin.send(JSON) to nih-plug parameter setters.
The Rust EditorHandler receives JSON messages, parses them, and calls ParamSetter.

The CLAP GUI extension in nih-plug should advertise the editor. clap-wrapper's wrappedview.mm
bridges the CLAP GUI to an AUCocoaView. The question is whether this chain actually works
end-to-end through AU in Logic Pro.

If AU GUI forwarding doesn't work, the CLAP and VST3 formats should still show the webview
when loaded directly in CLAP/VST3 hosts. AU users would get the generic parameter UI.
</context>
