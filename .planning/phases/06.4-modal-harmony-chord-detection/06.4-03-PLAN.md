In the piano keyboard widget (piano.rs):

1. **Scale tinting**: For each piano key, check if the note is in the current scale using `scale.is_in_scale(note)`. If in-scale, apply a subtle tint:
   - White keys in scale: slightly brighter or with a subtle gold/amber wash
   - Black keys in scale: slightly lighter shade
   - Out-of-scale keys: default color (no tint change)
   The tint should be subtle — just enough to see which notes are "available" in the current scale.

2. **Borrowed note highlighting**: When a note is currently sounding AND `engine.last_borrowed_from()` is Some, highlight that note in orange/amber (use the steampunk theme's accent color, likely around `Color32::from_rgb(204, 153, 0)` or similar amber). This is distinct from:
   - Input notes (existing blue/cyan color)
   - Harmony notes (existing green/purple color)
   - Generator notes (existing magenta color)

To implement, the piano widget needs access to:
- The current Scale (to check is_in_scale)
- Whether interchange produced the currently sounding notes (from engine.last_borrowed_from())

Pass this data through whatever mechanism the piano widget currently uses (likely via AppState or parameters). Look at how the piano currently receives `input_notes` and `harmony_notes` HashSets and follow that pattern.

The piano already has coloring logic — extend it, don't replace it. Borrowed note color takes priority over harmony color but not over input color.
