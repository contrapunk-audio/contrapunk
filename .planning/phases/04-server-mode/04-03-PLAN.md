<task type="auto">
  <name>Task 2: Implement client mode</name>
  <files>src/main.rs</files>
  <action>
Add a `run_client(addr: &str) -> Result<()>` function in main.rs, gated with `#[cfg(not(feature = "gui"))]`.

In the main() routing logic (from Task 1), handle the --client branch with cfg:
- `#[cfg(not(feature = "gui"))]`: call run_client(&addr)
- `#[cfg(feature = "gui")]`: print "Client mode requires CLI build (compile without --features gui)" and exit with code 1

**run_client implementation (~80 lines):**

1. Connect TcpStream to addr. Set nodelay(true), read_timeout(30s), write_timeout(5s).
2. Print "Connected to Contrapunk server at {addr}"
3. Prompt user for MIDI input port selection (reuse existing select_input_port).
4. Prompt user for MIDI output port selection (reuse existing select_output_ports).
5. Prompt user for key, mode, octave_mode (reuse existing select_key, select_mode, select_octave_mode).
6. Send Configure message to server with selected key, mode, octave_mode, voice_count (= number of output ports).
7. Wait for Ack.
8. Connect to local MIDI input (reuse connect_input with mpsc channel).
9. Create local OutputRouter for selected output ports.
10. Create a shared `Arc<AtomicUsize>` called `voice_counter`, initialized to 0.
11. Spawn reader thread: clone the TcpStream (or use a BufReader over a cloned stream). Loop calling protocol::read_message(). For each MidiData response received, compute output_index = voice_counter.fetch_add(1, Ordering::Relaxed) % voice_count, then route the MIDI bytes to output port at output_index via OutputRouter.
12. Main thread: loop reading from MIDI input channel (mpsc). For each MIDI message, reset voice_counter to 0 with voice_counter.store(0, Ordering::Relaxed), then send as MidiData via protocol::write_message(). Check for Enter key to stop (same pattern as existing CLI router).
13. On exit: send Disconnect message to server, close stream.

**Output routing algorithm (single clear approach):**
- Shared state: `Arc<AtomicUsize>` voice_counter between writer (main) and reader threads.
- Writer thread: on each new input MIDI note sent to server, store 0 into voice_counter.
- Reader thread: on each MidiData received from server, fetch_add(1) on voice_counter. Use (value % voice_count) as the output port index.
- This works because the server sends harmonized voices in order (voice 0, 1, 2...) and MIDI is processed one input note at a time.
