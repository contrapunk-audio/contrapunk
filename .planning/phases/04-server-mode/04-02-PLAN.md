  <action>
Create src/server/session.rs with:

**`handle_client(stream: TcpStream) -> Result<()>`:**
- Configure stream: set_nodelay(true), set_read_timeout(30s), set_write_timeout(5s)
- Create HarmonyEngine with default key (C) and mode (PassThrough)
- Set voice_count to 4 (default, configurable via Configure message)
- Loop reading messages via protocol::read_message():
  - MidiData(bytes): process through engine using the same pattern as router.rs process_midi_message. For NoteOn/NoteOff, call engine.harmonize_note_on/off, serialize all resulting notes as separate MidiData messages back to client. For non-note messages, echo back unchanged.
  - Configure { key, mode, octave_mode, voice_count }: update engine settings (convert u8 to Key/HarmonyMode/OctaveMode using from-index patterns). Send Ack back. On key/mode change, clear engine state.
  - Heartbeat: respond with Heartbeat
  - Disconnect: break loop
- On any read error (timeout, disconnect): log and break
- Before returning: send all-notes-off (CC 123, channel 0) as MidiData message to client (best-effort, ignore write errors)
- Log client connect/disconnect with peer address

Use wmidi for MIDI message parsing (same as router.rs). Import HarmonyEngine, Key, HarmonyMode, OctaveMode from crate::harmony.
  </action>
