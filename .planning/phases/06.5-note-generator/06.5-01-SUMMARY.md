# Phase 6.5 Plan 01: Generator Config and Engine Summary

**One-liner:** Tick-based NoteGenerator with 5 modes (HeldNotes, Chord, Arpeggio, ScaleRunner, RandomDiatonic) producing GeneratorEvents on beat boundaries

## What Was Done

### Task 1: Generator config types
Created `src/generator/` module with config types:
- `GeneratorMode` enum with 5 variants
- `ChordType` enum with 9 chord qualities and `intervals()` method
- `ArpDirection` enum (Up, Down, UpDown)
- `GeneratorEvent` enum (NoteOn with velocity, NoteOff)
- Module wired into main.rs and lib.rs

### Task 2: NoteGenerator engine
Implemented the core engine:
- `tick(beat_pos, bpm)` quantizes to step grid and generates events per mode
- Arpeggio supports Up, Down, and UpDown (bounce) directions
- `all_notes_off()` clears active notes and resets sequence state
- `set_mode()` and `set_selected_notes()` release active notes before switching
- `set_enabled(false)` sends NoteOff for all active notes
- 7 unit tests covering all key behaviors

## Deviations from Plan

None - plan executed exactly as written.

## Decisions Made

1. **HeldNotes and Chord share logic** — both play all selected notes simultaneously since chord tones are pre-resolved by UI
2. **Beat wrap-around detection** — if beat_pos < last_beat_position, treat as new step (handles bar resets)
3. **Initial last_beat_position = -1.0** — ensures first tick always triggers

## Verification

- `cargo check --features gui` passes
- `cargo test --features gui -- generator` — 7/7 tests pass
- All 5 GeneratorMode variants constructable
- ChordType::intervals() returns correct intervals for all 9 types

## Next Phase Readiness

Ready for Plan 02 (UI integration). NoteGenerator is fully platform-agnostic with no UI dependencies.
