  <files>src/app.rs</files>
  <action>
Add `generator: NoteGenerator` field to `ContrapunkApp` struct (initialize with `NoteGenerator::new()` in constructor).

In the WASM update path (inside `update()` where the app processes MIDI each frame):
- After beat clock tick, before or alongside physical MIDI drain:
- If `self.generator.enabled` and the app is running:
  - Get beat position from the beat clock (check existing accessor — likely `self.wasm_humanizer` or similar)
  - Get BPM from humanize config
  - Call `self.generator.tick(beat_pos, bpm)`
  - For each `GeneratorEvent::NoteOn(note, vel)`: call the same note-on handler used for physical MIDI (e.g., `handle_wasm_note_on` with `Channel::Ch1`)
  - For each `GeneratorEvent::NoteOff(note)`: call the same note-off handler

For the native path (router.rs): The generator will also need ticking. Add a similar pattern — if generator is enabled, tick it in the router loop and process events through the same harmony pipeline. Pass generator reference or events via the existing state sharing mechanism (Arc<Mutex> or message channel).

IMPORTANT: Generator notes MUST go through the same `harmonize_note_on()` path as physical MIDI. Do NOT create a separate processing path.

Handle the "generator enabled independently" pattern: generator.enabled is a separate toggle from the input device selection. When generator is enabled, it runs even if a physical MIDI device is also selected (dual-source merging per success criterion 6).
  </action>
  <verify>cargo check passes for both default and wasm targets</verify>
  <done>Generator ticks each frame, events flow through harmonize_note_on/off, works alongside physical MIDI.</done>
