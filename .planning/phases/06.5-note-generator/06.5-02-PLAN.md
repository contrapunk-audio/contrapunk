**WASM path (src/app.rs):**

Add `generator: NoteGenerator` field to `ContrapunkApp` struct (initialize with `NoteGenerator::new()` in constructor).

In the WASM update path (inside `update()` where the app processes MIDI each frame):
- After beat clock tick, before or alongside physical MIDI drain:
- If `self.generator.enabled` and the app is running:
  - Get beat position from the beat clock (check existing accessor — likely `self.wasm_humanizer` or similar)
  - Get BPM from humanize config
  - Call `self.generator.tick(beat_pos, bpm)`
  - For each `GeneratorEvent::NoteOn(note, vel)`: call the same note-on handler used for physical MIDI (e.g., `handle_wasm_note_on` with `Channel::Ch1`)
  - For each `GeneratorEvent::NoteOff(note)`: call the same note-off handler

**Native path (src/router.rs):**

The native router runs in a separate thread (`spawn_gui_router` / `run_gui_router_inner`). The generator must be handled differently from WASM because state lives in a different thread.

1. Add generator config fields to `GUIRouterState`:
   - `generator_enabled: bool` — GUI sets this when user selects Note Generator
   - `generator_config: Option<GeneratorConfig>` — GUI writes updated config (mode, selected_notes, duration, velocity); router takes it via `.take()`

2. Create a `NoteGenerator` locally inside `run_gui_router_inner()` (same pattern as HarmonyEngine — created inside the thread, not shared via Arc):
   ```rust
   let mut generator = NoteGenerator::new();
   ```

3. In the main routing loop (after `humanizer.tick(current_ms)` and config sync block, BEFORE the `rx.recv_timeout` physical MIDI section):
   - Sync generator config from shared state:
     ```rust
     {
         let mut state_lock = state.lock().unwrap();
         generator.enabled = state_lock.generator_enabled;
         if let Some(config) = state_lock.generator_config.take() {
             generator.apply_config(config);
         }
     }
     ```
   - If generator is enabled, tick it using the humanizer's beat clock:
     ```rust
     if generator.enabled {
         let beat_pos = humanizer.clock().beat_position();
         let bpm = humanizer.config().bpm; // or however BPM is accessed
         let events = generator.tick(beat_pos, bpm);
         for event in events {
             match event {
                 GeneratorEvent::NoteOn(note, vel) => {
                     let velocity = Velocity::try_from(vel).unwrap_or(Velocity::MAX);
                     handle_note_on_gui(Channel::Ch1, note, velocity, &mut engine, &mut output_router, &state, &mut humanizer, &mut delay_queue, current_ms)?;
                 }
                 GeneratorEvent::NoteOff(note) => {
                     handle_note_off_gui(Channel::Ch1, note, Velocity::MIN, &mut engine, &mut output_router, &state, &mut humanizer, &mut delay_queue, current_ms)?;
                 }
             }
         }
         ctx.request_repaint();
     }
     ```

4. **Event ordering:** Generator events are processed FIRST (before the `rx.recv_timeout` block), then physical MIDI events. Both go through the same `handle_note_on_gui` / `handle_note_off_gui` functions, which call `engine.harmonize_note_on()`. This ensures identical harmony processing for both sources within the same loop iteration.

IMPORTANT: Generator notes MUST go through the same `harmonize_note_on()` path as physical MIDI. Do NOT create a separate processing path.

Handle the "generator enabled independently" pattern: generator.enabled is a separate toggle from the input device selection. When generator is enabled, it runs even if a physical MIDI device is also selected (dual-source merging). Both sources feed into the same harmony engine and output router.
