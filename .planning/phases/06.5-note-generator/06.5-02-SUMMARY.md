# Phase 6.5 Plan 02: Generator Integration Summary

Wire NoteGenerator into both processing paths, add "Note Generator" and "Computer Keyboard" as virtual inputs in the IN dropdown with QWERTY piano mapping.

## What Was Done

### Task 1: Wire NoteGenerator into WASM and native processing

- Added `generator_enabled`, `generator_mode`, `generator_selected_notes`, `generator_velocity`, `generator_note_duration_beats`, `keyboard_events`, `keyboard_enabled` fields to `GUIRouterState`
- Created `NoteGenerator` locally inside the router thread
- Ticked generator in native router loop after state sync, feeding events through `handle_note_on_gui`/`handle_note_off_gui`
- Ticked generator in WASM update loop after beat clock tick, feeding events through `handle_wasm_note_on`/`handle_wasm_note_off`
- Added `BeatClock::beat_position()` getter for generator beat synchronization
- Synced generator state (enabled, velocity, duration) from GUI to router shared state each frame
- Collected pending generator note-off events before dropping lock to avoid deadlock

### Task 2: Add virtual inputs to IN dropdown

- Added "Note Generator" and "Computer Keyboard" entries to IN device dropdown (both native and WASM)
- Used sentinel values: `INPUT_NOTE_GENERATOR = usize::MAX`, `INPUT_COMPUTER_KEYBOARD = usize::MAX - 1`
- Implemented `on_input_port_changed()` to handle virtual input selection: enables/disables generator and keyboard, sends all_notes_off on switch
- Implemented `key_to_midi_note()` QWERTY piano mapping (Z-M = C3-B3 white keys, S/D/G/H/J = sharps; Q-U = C4-C5 white keys, 2/3/5/6/7 = sharps)
- Tracked held keys in `keyboard_held_keys: HashSet<u8>` for proper NoteOff on release
- Modified native `try_start`: skip physical MIDI connection for virtual inputs
- Modified WASM `try_start`: skip Web MIDI access requirement and physical input for virtual inputs
- Native keyboard events pushed to `GUIRouterState::keyboard_events`, processed by router thread
- WASM keyboard events processed directly in update() via `ctx.input()` event scanning

## Deviations from Plan

### Additional User Requirement

**"Computer Keyboard" virtual input** was added alongside "Note Generator" per user request. This was not in the original plan but was specified as an additional requirement. Implemented as a full QWERTY piano with key tracking and proper NoteOff handling.

### Auto-fixed Issues

**1. [Rule 3 - Blocking] BeatClock::beat_position() getter missing**
- Found during: Task 1
- Issue: Generator tick needs current beat position, but BeatClock only returned it from tick()
- Fix: Added public `beat_position()` getter to BeatClock
- Files modified: src/humanize/beat_clock.rs
- Commit: c9ba701

**2. [Rule 1 - Bug] Deadlock in generator state sync**
- Found during: Task 1
- Issue: Generator note-off processing called handle_note_off_gui (which locks state) while state_lock was held
- Fix: Collected pending events, dropped lock, then processed events
- Files modified: src/router.rs
- Commit: c9ba701

**3. [Rule 3 - Blocking] Virtual inputs fail try_start physical connection**
- Found during: Task 2
- Issue: try_start assumed physical MIDI input, would fail for sentinel indices
- Fix: Skip physical connection when input_port >= usize::MAX - 1
- Files modified: src/app.rs, src/router.rs
- Commit: ccad756
