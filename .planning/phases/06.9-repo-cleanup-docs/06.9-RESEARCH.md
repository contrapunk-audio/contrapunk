## Common Pitfalls

### Pitfall 1: Losing Useful Information
**What goes wrong:** Deleting legacy files without capturing useful ideas/data
**Why it happens:** Rush to clean up without reviewing content
**How to avoid:** Extract ideas list from README and chord/rhythm data from main.py BEFORE deletion
**Warning signs:** Deleting files without reading them first

### Pitfall 2: Breaking Git History
**What goes wrong:** Using git filter-branch or BFG to rewrite history
**How to avoid:** Use simple `git rm` — the files remain in history (which is fine), just removed from HEAD
**Warning signs:** Urge to "completely remove" files from repo history

### Pitfall 3: Incomplete .gitignore Update
**What goes wrong:** target/ directory gets committed
**Why it happens:** .gitignore doesn't have Rust entries
**How to avoid:** Add target/ to .gitignore BEFORE any build artifacts are committed. Also need to `git rm -r --cached target/` if it was already tracked.
**Warning signs:** Huge diffs containing compiled artifacts

### Pitfall 4: dist/ Directory Confusion
**What goes wrong:** dist/ is in .gitignore but contains tracked files
**Why it happens:** Files were committed before .gitignore entry was added
**How to avoid:** `git rm -r --cached dist/` to untrack while keeping in .gitignore
