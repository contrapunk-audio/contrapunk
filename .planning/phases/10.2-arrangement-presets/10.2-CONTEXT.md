# Phase 10.2: Composer-Informed Arrangement Presets — Context

**Created:** 2026-07-19
**Status:** Planned for iterative execution
**Catalog:** [10.2-PRESET-CATALOG.md](./10.2-PRESET-CATALOG.md)
**Research template:** [10.2-RESEARCH-TEMPLATE.md](./10.2-RESEARCH-TEMPLATE.md)

## Goal

Ship 50 musically distinct, technique-named global arrangement presets with composer references, performer guidance, immutable built-ins, editable Save As copies, honest capability gating, and deterministic note cleanup. Presets configure real arrangement behavior; unsupported entries must never masquerade as working.

## Locked product decisions

1. Public preset titles use techniques or imagery. Composer names are references/influences only.
2. Every preset contains **Result** and **Play it like** guidance. Guidance remains visible after Apply.
3. Built-ins are immutable. Users customize through Duplicate/Save As.
4. User presets capture both musical metadata and the current arrangement snapshot.
5. Presets preserve tonic, BPM, time signature, input device, guitar config, external port assignments, audio device, master level, mute/solo, hosted plugins, and transport running state.
6. Presets may change scale character, harmony, voice layout, Companion lanes, Hold behavior, and base role gains.
7. Sound design is separate. A preset may recommend a sound preset but does not silently replace it.
8. All 50 catalog records are authored first. Apply is enabled only when declared capabilities exist on the current surface.
9. Temporal behavior becomes a Companion `Lane`; stateless note-to-pitch mapping becomes a harmony strategy.
10. The current production UI and the isolated native prototype consume one shared preset store/catalog.
11. Plugin surfaces remain capability-gated until Companion parity exists; no visible lies.
12. Elixir, Golem, AU wrapper, recon, and unrelated dirty-tree work remain outside this phase.
13. A preset cannot become operational until three independent research perspectives have produced a cited research pack following `10.2-RESEARCH-TEMPLATE.md`: historical/primary-source context, music-theory and temporal-behavior translation, and performer/interaction guidance. Research must scope the referenced artist's works/period, explain persistent versus period-specific traits, show how material evolves within phrases/sections and across the artist's career, distinguish the artist from shared genre vocabulary, and identify caricatures to avoid. The parent synthesizes those reports into explicit musical invariants, evolution states/transitions, acceptable approximations, and tests before implementation.
14. The execution loop must hard-stop after the first twelve operational presets. It presents automated evidence and a playable build/instructions for user testing, and cannot begin Wave 3 without explicit user approval.

## ArrangementPresetV2 contract

Each record owns:

- stable ID, name, family, tags, built-in flag;
- result description;
- structured play guidance: prompt, input type, articulation, density, spacing, tempo guidance, transport requirement;
- structured composer references with context;
- declared capability requirements and availability;
- harmony snapshot: scale mode, harmony mode, voice count/position, leading, octave placement/intensity, interchange, species/strictness;
- Companion snapshot: enabled, global Hold, stable lane instances, lane/voice Hold and complete configs;
- base Input/Harmony/Canon/Counterpoint mix gains;
- optional suggested sound preset ID.

Transient hardware, transport, and performance state is excluded.

## Safety prerequisites

Before adding more delayed behavior:

- reproduce the reported Free Imitation release issue under effective voice > lane > global Hold resolution;
- test Cancel/Near Future/Phrase End/Forever with running and stopped transport;
- make preset replacement issue one Panic, reset every lane runtime, validate, and apply atomically;
- ensure every Lane tracks source ownership, emits matching NoteOff, clears on disable/Panic/reconfigure, and bounds queues/event rate;
- never run the sealed guitar holdout without explicit authorization.

## Execution waves

### Wave 1 — Safety and preset foundation (`10.2-01`)

- Fix or conclusively document Free Imitation release semantics with a regression.
- Add `ArrangementPresetV2`, typed capability IDs, `ArrangementConfig`, and versioned persistence/migration.
- Centralize presetable counterpoint and mix state currently trapped in components.
- Add transactional apply: Panic once, reset runtime, validate, apply, UI commit/rollback.
- Add adapter capability gating across Tauri/WASM/plugin.

**Exit:** a synthetic preset round-trips and applies without orphan notes or partial state.

### Wave 2 — Catalog, research packs, authoring UX, and baseline twelve (`10.2-02`)

- Add all 50 catalog records as drafts from the accepted catalog; unfinished records remain visibly research-pending and cannot Apply.
- For each baseline preset, run three fresh-context, read-only research passes in parallel:
  1. **Artist/style history and primary sources:** scope specific works and periods; trace career/style evolution, persistent versus period traits, relationship to peers, and common caricatures to avoid.
  2. **Music theory and temporal behavior:** translate harmony, melody, voice motion, rhythm, texture, register, dissonance, phrase, and form into testable rules; model how material accumulates, fragments, modulates, thins, returns, and cadences over time.
  3. **Performance/HCI:** define what a live guitarist/keyboardist should play, how the player develops material through a phrase/section, timing/space/transport needs, listening cues, failure gestures, and useful UI wording.
- Save cited outputs under `research/NN-slug/`, then create a parent-authored `synthesis.md` using the research template. It must include the referenced period/corpus, style thesis, invariants, within-phrase and across-section evolution model, rejected caricatures, approximations, exact config/capability mapping, performer contract, and acceptance examples. Fewer than three successful perspectives blocks activation.
- Add detail browser with Result, Play it like, references, requirements, research status, and availability.
- Expand Save As to collect user-authored musical guidance and snapshot the arrangement.
- Keep all unsupported records locked with a precise missing-feature explanation.
- Implement and validate the twelve baseline presets in this order: 2, 4, 7, 8, 12, 14, 23, 25, 27, 36, 43, 48.

**Exit and hard human checkpoint:** exactly 50 unique draft records exist; twelve research-backed presets Apply and end with zero active notes. Produce a test report and playable instructions, then stop. Wave 3 is forbidden until the user tests and explicitly approves continuation.

### Wave 3 — Voicing strategies (`10.2-03`, after explicit approval)

Add reusable harmony strategies, not preset-specific branches:

- explicit scale-degree/semitone interval stacks;
- inversion around an axis;
- tintinnabuli nearest-triad rules;
- extensions, root omission, guide tones, drop voicings;
- bounded clusters and register constraints;
- partial-derived/microtonal voicing behind honest capability gates.

**Exit:** voicing-dependent presets unlock without one-off algorithms.

### Wave 4 — Phrase and motif lane (`10.2-04`)

Add one bounded phrase/motif Lane supporting:

- capture, loop, reverse, transpose;
- augmentation/diminution and fine ratios;
- fragmentation/recombination;
- motif identity, recurrence, and two named motif slots;
- strict source ownership and Hold semantics.

**Exit:** reverse, phase, fragment, recurrence, and leitmotif presets unlock with lifecycle tests.

### Wave 5 — Pattern and advanced timing lane (`10.2-05`)

Add one data-driven Pattern Lane supporting:

- step grids, ostinato, Alberti, arpeggio, bass/chord alternation, clave, additive patterns;
- accents, swing, odd meter, independent lane meter, polymeter, phase reset;
- shared synchronization boundaries and stopped-transport cleanup.

**Exit:** pattern/comping/groove/cross-rhythm presets unlock without separate engines.

### Wave 6 — Stable groups, harmonic timeline, adaptive scenes (`10.2-06`)

- Give every Lane instance a stable ID, mix group, register, output target, serialization, and activity attribution.
- Permit multiple instances of a Lane type without ambiguous `type_id` restoration.
- Add a Mutate-phase harmonic timeline for key offsets, scale/mode changes, side-slips, cycles, and weighted transitions.
- Add a Sense-phase intensity model using density, velocity, register, phrase length, silence, and repetition.
- Support only three adaptive scene states initially: Sparse, Building, Full.

**Exit:** antiphonal, sectional, modulation, and adaptive presets unlock.

### Wave 7 — Experimental completion and all-50 acceptance (`10.2-07`)

- Finish bounded micro-delay, per-voice detune, probability/density, chromatic cluster, independent tonal-center, and spectral capabilities.
- Tune every preset for audible differentiation and useful play guidance.
- Run catalog, lifecycle, cross-surface, UI, and representative performance acceptance.
- Keep unsupported plugin capabilities visibly gated rather than faked.

**Exit:** all 50 are either operational on a supported surface or explicitly blocked by a documented external surface limitation; no internal feature remains a placeholder.

## Verification contract

After each non-trivial slice, run the narrowest relevant checks. At wave boundaries run:

```bash
cargo test -p contrapunk-companion --lib
cargo test -p contrapunk-harmony --lib
cargo check --workspace --message-format=short
npm --prefix ui run check
```

Also run `npm --prefix ui run build:wasm` when WASM bindings change. Guitar release tests are required only if guitar code changes, which this phase should avoid.

Data-driven acceptance must prove:

- exactly 50 unique built-in IDs and names;
- nonempty Result/Play/reference metadata;
- three cited research reports plus a parent synthesis for every operational preset;
- the synthesis states musical invariants, approximations, input contract, and acceptance examples;
- valid capability IDs and configs;
- built-ins immutable and user presets round-trip/migrate;
- unsupported presets cannot Apply;
- each operational preset processes a fixed NoteOn/NoteOff sequence and ends with zero active or pending notes;
- Panic and preset replacement clear all runtime state.
