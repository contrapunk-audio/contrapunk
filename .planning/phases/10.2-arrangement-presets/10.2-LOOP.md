# Agent Loop: Contrapunk 50 Arrangement Presets

## Objective

Execute Phase 10.2 through the first twelve operational presets, then hard-stop for user performance testing. Each operational preset must first receive three independent, cited research perspectives and a parent synthesis. After explicit user approval, resume later waves until the accepted 50-preset catalog is implemented with honest capability gating, editable user metadata, deterministic application, and zero orphaned notes. Build reusable harmony strategies and Companion lanes rather than preset-specific branches.

## Persistent state

Each iteration reads and updates:

- `.planning/phases/10.2-arrangement-presets/10.2-CONTEXT.md`
- `.planning/phases/10.2-arrangement-presets/10.2-PRESET-CATALOG.md`
- `.planning/phases/10.2-arrangement-presets/10.2-RESEARCH-TEMPLATE.md`
- `.planning/phases/10.2-arrangement-presets/10.2-STATE.json`
- `.planning/STATE.md`
- relevant tests and `git status --short`

`10.2-STATE.json` tracks current wave, current slice, completed requirements, operational preset IDs, locked preset IDs with reasons, per-preset research status/artifact paths, commands/evidence, blockers, decisions, last commit, user-checkpoint status, and exact next action.

## Iteration prompt

> Continue Phase 10.2 from its saved state. Read the phase context, catalog, state JSON, current git status, and recent commits. Select the smallest unblocked slice in the current wave that advances an explicit exit criterion. Trace the complete call path before editing and reuse the existing HarmonyEngine, Companion Lane phases, adapters, and stores. Do not create preset-specific algorithms when a typed data field, shared harmony strategy, or reusable Lane covers the need.
>
> Before implementing or finalizing any preset, read `10.2-RESEARCH-TEMPLATE.md`, inspect available subagents, then launch three fresh-context read-only research tasks in parallel: artist/style history and primary sources, music theory and temporal behavior, and performer/interaction guidance. Research must scope specific works and periods, explain how the artist's style changes across a career, separate persistent traits from period-specific techniques, distinguish shared genre language from unusually characteristic choices, and model how the music evolves within phrases and sections—not merely name a scale or chord. Require authoritative citations, confidence, gaps, and concrete implications; save separate artifacts under `.planning/phases/10.2-arrangement-presets/research/NN-slug/`. Do not count duplicated unsourced summaries as independent evidence. The parent must synthesize the three reports into `synthesis.md` using the template, including a style thesis, phrase/section evolution states and triggers, stylistic invariants, caricatures to avoid, acceptable engine approximations, the Play-it input contract, exact config/capabilities, and acceptance examples. A preset cannot become operational without all four artifacts.
>
> Implement one coherent slice as the sole writer. Add the smallest deterministic regression that fails without the change, especially for branches, scheduling, preset migration/application, and NoteOff ownership. Run narrow checks immediately, then the wave-required checks when a boundary is reached. Inspect the focused diff and staged paths. Never stage unrelated work or `.pi-subagents/`. Commit the verified slice with explicit paths. Update `10.2-STATE.json` and `.planning/STATE.md` with research paths, evidence, residual risk, and the exact next slice. If the slice cannot be completed safely, checkpoint the blocker and move to another independent item only when doing so cannot hide the blocker.

## Verification

Per slice:

- focused unit/integration test for changed Rust logic;
- `npm --prefix ui run check` for UI/store/adapter changes;
- `npm --prefix ui run build:wasm` for WASM binding changes;
- `git diff --check` and explicit staged-path inspection.

At each wave boundary:

- `cargo test -p contrapunk-companion --lib`
- `cargo test -p contrapunk-harmony --lib`
- `cargo check --workspace --message-format=short`
- `npm --prefix ui run check`
- catalog validation and fixed input lifecycle simulation for every operational preset;
- research gate validation: three nonempty cited reports plus template-complete `synthesis.md` for each operational preset;
- every synthesis identifies a specific corpus/period, persistent versus period traits, within-phrase and across-section evolution, distinguishing features, rejected caricatures, and abstract non-copyrighted examples.

## Reflection cadence

- End of every iteration: assess whether the next slice is still the shortest path to the current wave exit.
- After each preset research synthesis: challenge whether the proposed rules capture the referenced technique rather than a superficial label.
- Every four newly operational presets: compare outputs/guidance for musical differentiation and ask a fresh research reviewer to identify caricatures, conflations, or unsupported claims.
- End of every wave: architecture, research-quality, and lifecycle review before opening the next wave.
- After two failed approaches to the same slice: stop coding, record evidence, and choose a different strategy.

## Stop rules

Hard-stop successfully after Wave 2 when the first twelve operational presets pass research, catalog, UI, and lifecycle acceptance. Produce a test report and exact user performance checklist. Do not begin Wave 3 until the user explicitly approves continuation.

After that approval, the final successful stop is when all Wave 7 exit criteria and ARRP requirements pass.

Pause and request a human decision when:

- the first twelve operational presets are complete and ready for user testing;
- fewer than three independent research perspectives can be completed for a preset;
- research sources disagree on a stylistic invariant that changes implementation;
- a manual musical/UI judgment is the only remaining evidence;
- a surface requires external hardware, DAW, signing, or credentials;
- a change would alter tonic/tempo/device/routing/sound ownership decisions;
- a destructive or broad Git operation appears necessary;
- unrelated dirty-tree edits overlap the required files;
- three command attempts fail for the same environmental reason;
- the sealed guitar holdout would be run.

Stop the current slice and checkpoint when tests reveal orphaned notes, unbounded scheduling, audio-callback allocation/blocking, or a preset that claims unsupported behavior.

## Guardrails

- Do not launch GUI applications unless the user explicitly requests it.
- Research subagents are read-only and use fresh context. Run at most three concurrently per preset; the parent remains the only writer and synthesizer.
- Before every research fanout, use subagent discovery and only run executable/non-disabled agents. If providers are unavailable, checkpoint rather than inventing multiple personas.
- Prefer primary sources, scholarly analysis, composer interviews, reputable institutions, and score-based evidence; record URLs, publication details, relevant work/measure/timestamp when available, and retrieval dates.
- Never reduce an artist to one famous work, scale, instrument, timbre, or chord trick. Multiple-reference presets must document the true intersection and excluded differences.
- Do not touch Elixir, Golem, AU wrapper, recon, `.pi-subagents/`, or unrelated documentation.
- Do not broaden guitar claims or modify detector thresholds.
- Keep sound presets separate from arrangement presets.
- Built-ins are immutable; user customization is Duplicate/Save As.
- Unsupported catalog entries stay visible but cannot Apply.
- All temporal queues and note ownership must be bounded and resettable.
- Prefer deletion/reuse over new abstractions; the existing Lane phase model is the temporal extension point.
